RefMatch 0.4.1 runtime candidate - 2026-09-21

Base: the 0.4 StreamMode package with the previous compile fixes retained.
No OAuth, no reference routing into plugin output, same visual direction.

Implementation:
- Plugin code no longer executes AppleScript or sends Apple Events.
- A Cocoa helper, com.refmatch.audio.control, is embedded in each AU/VST3/app.
  NSWorkspace/LaunchServices opens the helper as an application, rather than
  spawning a command-line subprocess under Logic's identity.
- The helper owns NSAppleEventsUsageDescription and the automation.apple-events
  entitlement. Changing the plugin plist cannot change Logic's entitlements.
- The helper calls AEDeterminePermissionToAutomateTarget; only explicit
  authorise requests allow a consent prompt. Fixed Spotify commands only.
- Asynchronous request/reply uses per-request UUIDs, helper PID targeting,
  main-thread callbacks and bounded timeouts. No scripts on the audio thread.
- Metadata uses an AppleScript list, integer milliseconds and explicit UTF-8.
- SWITCH fades the DAW mix before PLAY, waits for command confirmation, and
  restores MIX on failure. Returning to MIX restores the mix even if PAUSE
  fails; the error remains visible so the user can stop Spotify manually.
- The external Spotify signal is never processed. Only the mix gets a 20 ms
  cosine fade; a sample-synchronised two-source crossfade is not possible here.
- UI remains the dark cyan/violet StreamMode layout. Minimum height now keeps
  the controls visible; setup, permission errors and capture status are separate.
- Shared/weak capture state and request generations avoid stale capture
  callbacks dereferencing deleted state or reviving a cancelled start.

Build:
cmake -S RefMatch-0.4-StreamMode-SOURCE/RefMatch -B build   -DCMAKE_BUILD_TYPE=Release -DCMAKE_OSX_DEPLOYMENT_TARGET=13.0 -DBUILD_TESTING=ON
cmake --build build --config Release --parallel
ctest --test-dir build -C Release --output-on-failure

Use the new root .github/workflows/main.yml. Do not apply the old blanket
codesign --deep --force step, which may strip the helper's entitlements.
CMake embeds/signs the helper inside-out before signing the enclosing bundle.

Local verification:
- Plists parsed successfully with Apple's plutil.
- Reviewed file inventory, source references, workflow YAML and generated diff.
- Local configure attempted; blocked because cmake is not installed.
- Xcode/Command Line Tools are also absent.
- C++ regression tests are included and wired into CTest/GitHub Actions, but
  have NOT run locally. No successful compile, TCC prompt or Logic test claimed.

Manual acceptance after CI succeeds:
1. Clean grant: CONNECT prompts for RefMatch Control -> Spotify; accept.
2. Deny: clear explanation, MIX stays audible, settings/reconnect recover.
3. PLAY/PAUSE, previous/next, Unicode names (e.g. Bjork with diacritics),
   titles containing "|" and non-ASCII searches work.
4. Repeated SWITCH clicks do not enqueue duplicate commands.
5. At 44.1/48/96 kHz, MIX fades to zero and returns without abrupt jumps.
6. Stop/restart DAW playback; switch back to MIX with permission revoked.
7. Close/reopen the editor, remove plugin during capture start, and repeat.
8. Verify AU inside Logic and Standalone separately. SYSTEM AUDIO READY is
   independent from Spotify Automation permission.
9. Test installation over an old build after quitting Logic and the RM helper.

Known validation limits:
- Helper TCC attribution and host-specific sandbox behavior require real Logic
  testing. No host signatures, entitlements or TCC database are modified.
- Ad-hoc signed development builds may need a fresh permission grant after
  replacement. Stable distribution requires Developer ID signing/notarisation.
- Existing system capture still measures other external apps, not just Spotify.
- Multiple RefMatch instances control the same Spotify player; use one active
  reference instance on the master bus.
- Capture resampling/realtime allocation behavior has not been redesigned.
